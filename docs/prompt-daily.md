# 클로드 루틴 프롬프트 — 데일리

매일 새벽 실행되는 원격 예약 루틴. GitHub Actions가 만든 `data/latest.json`을 읽어 상위 5건을 골라 요약하고 노션에 기록한다.

- **입력**: `data/latest.json` (curl 1회)
- **출력**: 노션 통합 뉴스 DB (`create-pages` 2회 — 뉴스 + 추출실패 배치, 그리고 데일리 브리핑)
- **중단 가드**: fetch 실패 / 요약본만 반환 / `generated_at` 날짜가 오늘(KST)이 아님


## 사용 전 치환할 값

이 문서의 프롬프트는 비밀값이 플레이스홀더로 치환되어 있다. 클로드 루틴에 넣기 전에 자신의 값으로 바꾼다.

| 플레이스홀더 | 바꿀 값 | 찾는 곳 |
|---|---|---|
| `YOUR_GITHUB_USERNAME` | GitHub 사용자명 | 저장소 URL |
| `YOUR_NOTION_DATA_SOURCE_ID` | 노션 데이터 소스 ID | 노션 MCP로 대상 DB 조회 시 응답에 포함 |
| `YOUR_NOTION_DATABASE_ID` | 노션 데이터베이스 ID | 노션 DB URL의 32자리 문자열 |
| `YOUR_NOTION_TOKEN` | 노션 Integration Token | notion.so/my-integrations |
| `YOUR_SLACK_WEBHOOK_URL` | 슬랙 Incoming Webhook URL | 슬랙 앱 설정 |

**치환한 프롬프트는 클로드 루틴 설정에만 넣고 저장소에 커밋하지 않는다.** 로컬 파일로 두더라도 git 추적에서 제외한다.

---

## 프롬프트 전문

아래 블록 전체를 그대로 클로드 루틴에 넣는다.

````markdown
자동 실행. 확인 질문 금지. 모든 결정은 알아서 합리적으로.
검색 금지. 재작성 루프 금지. 생성 후 재조회 금지.
items와 extract_failed만 사용. dropped_below_threshold와 keywords_snapshot은 무시.
추정 환각 절대 금지. JSON에 명시된 값만 사용. JSON에 없는 기사 생성 금지.

---
## 1. JSON 읽기 + 신선도 검증 (한 번에)

bash: curl -s "https://raw.githubusercontent.com/YOUR_GITHUB_USERNAME/news-automation/main/data/latest.json"

- 한 번만 호출. 재요청 금지.
- curl은 요약 없이 원본 JSON 그대로 반환.

**아래 중 하나라도 해당되면 즉시 전체 작업 중단. 노션 기록 절대 금지.**

(a) fetch 실패 또는 응답이 JSON이 아님
    → "⚠️ 중단: latest.json fetch 실패. 노션 기록 안 함"

(b) 응답에 items 배열 전체(stats.extracted_success 건수만큼)가 안 보임. 요약본만 반환됨
    → "⚠️ 중단: JSON 요약본만 반환됨. 원본 fetch 필요. 노션 기록 안 함"

(c) **generated_at의 날짜(YYYY-MM-DD)가 오늘(KST) 이 아님**
    오늘 새벽 루틴은 오늘 날짜로 갱신된 JSON만 처리한다.
    generated_at 날짜 != 오늘(KST) 이면 = JSON 갱신 실패(cron 또는 Actions 누락)로 간주.
    → "⚠️ 중단: latest.json이 오늘 갱신 안 됨. generated_at: {값} / 오늘(KST): {오늘날짜}. JSON 갱신 실패로 추정. 노션 기록 안 함"

중단 시 2번 이후 단계로 절대 진행하지 않는다.
어떤 경우에도 갱신 안 된 JSON으로 페이지를 만들지 않는다(중복 페이지 원인).

## 2. LLM 점수 + 선정 (한 번에)

items 전체 대상. title + summary 기준 LLM 점수 0~10.
기준: 반도체 산업 관련성 / 정보 밀도 / 중복성
**우선 가중**: 공정·양산 기사(특히 박막공정 — 증착·ALD·CVD·PVD 등)는 같은 조건이면 시황·주가성보다 위로. 사용자 우선순위.

final_score = items[].score × 0.3 + llm_score × 0.7
(items[].score는 이미 0~10 정규화됨)

내림차순 정렬 후 상위 5건 선정. items가 5건 미만이면 있는 만큼.
JSON에 없는 기사 추가 금지. 추정으로 채우기 금지.
재채점 금지.

**영문 쿼터**: items 중 제목에 한글이 하나도 없는 기사(=영문 기사)가 있으면,
상위 5건에 영문 기사를 최소 1건 포함한다.
- final_score 상위 5에 영문이 이미 들어 있으면 그대로 둔다.
- 없으면, 영문 기사 중 final_score가 가장 높은 1건을 5위 기사와 교체해 포함한다.
- 영문 기사가 items에 아예 없으면 이 규칙은 무시(한글로만 5건).
- 영문도 final_score는 그대로 사용. 요약/카테고리 규칙은 한글과 동일.

## 3. 요약 + 카테고리 (초안 = 최종본)

**헤드라인**: "M/D 원제목" 형식만 사용.
- M/D: items[].date의 월/일 (앞 0 없음)
- M D 둘 다 앞 0 없음. 한 자리면 그대로. 06/05 6/04 6/05 전부 금지 → 6/4 6/5
- 원제목: items[].title 그대로
- 추가 접두사 접미사 절대 금지

**카테고리** (해당되는 것 모두 선택, 최소 1개):
- 메모리: DRAM, HBM, NAND, 메모리
- 파운드리: 위탁생산, 공정, TSMC, 삼성파운드리
- 장비소재: ASML, 포토레지스트, 소부장, 장비
- 설계: 팹리스, AP, GPU, 칩 설계
- 글로벌: 미중 규제, 수출통제, 보조금, 지정학

**요약**: items[].body 기반 2문장, 각 80자 이내. 직접 인용 금지.
body에 없는 내용 추가 금지.
재작성 금지. 초안 그대로.

---

## 4. 데일리 브리핑 작성 (초안 = 최종본)

선정 기사 종합:
- 3~4문장, 각 문장 100자 이내 (총 400자 이내)
- 가장 중요한 흐름 1~2개만. 모든 기사를 다 언급할 필요 없음.
- 빈 줄
- "인사이트: " + 1문장

날짜: 선정 기사들의 items[].date 중 최빈값의 M/D
헤드라인: "M/D 반도체 데일리 브리핑"

---

## create-pages 속성 형식 (정확히 이대로. 추측 금지)

한 page의 properties 구조 예시:
```json
{
  "헤드라인": "6/4 원제목 - 매체",
  "date:날짜:start": "2026-06-04",
  "date:날짜:is_datetime": 0,
  "분야": "[\"반도체\"]",
  "카테고리": "[\"메모리\",\"파운드리\"]",
  "요약": "두 문장.",
  "링크": "https://..."
}
```

핵심 규칙:
- 분야, 카테고리는 multi_select. JSON 배열을 문자열로 감싸서 넣는다.
  - 맞음: "[\"메모리\",\"글로벌\"]"
  - 틀림: "메모리,글로벌"   (쉼표 문자열. 거부됨)
  - 틀림: ["메모리","글로벌"]   (실제 배열. 거부됨)
  - 1개일 때도 배열: "[\"반도체\"]"
- 카테고리 옵션은 정확히 이 6개 중에서만: 데일리 브리핑, 메모리, 파운드리, 장비소재, 설계, 글로벌
  - 이 외 값, 오타 1글자, 띄어쓰기 차이도 거부됨.
- 비울 땐 빈 문자열 ""
- date는 확장키 사용: "date:날짜:start", "date:날짜:is_datetime": 0
- 링크 속성명은 "링크" 그대로 (userDefined 접두사 없음)

이 형식대로 한 번에 보낸다. 거부되면 재시도하지 말고 위 규칙과 대조해 형식만 고쳐 1회 재전송.

## 5. 노션 1회차 — 뉴스 + 추출실패 배치 (한 번에)

extract_failed에서 score 내림차순 상위 5건 추출 (5건 미만이면 있는 만큼).
제목 보고 카테고리 추정. 애매하면 비움.

notion create-pages, parent: data_source_id = YOUR_NOTION_DATA_SOURCE_ID

선정 뉴스 + 추출실패를 한 번에 생성. 속성 형식은 위 "create-pages 속성 형식" 그대로.

선정 뉴스 페이지:
- 헤드라인: "M/D items[].title" (접두사 접미사 금지)
- date:날짜:start: items[].date 그대로
- date:날짜:is_datetime: 0
- 분야: "[\"반도체\"]"
- 카테고리: 3단계 판단값 (배열 문자열)
- 요약: 3단계 작성값
- 링크: items[].url 그대로 (다른 url 절대 금지)

추출실패 페이지:
- 헤드라인: "M/D extract_failed[].title" (접두사 접미사 금지)
- date:날짜:start: 4단계 날짜
- date:날짜:is_datetime: 0
- 분야: "[\"반도체\"]"
- 카테고리: 제목 추정값 배열 문자열 (애매하면 "")
- 요약: ""
- 링크: extract_failed[].url 그대로 (다른 url 절대 금지)

선정 뉴스와 추출실패 페이지 url 모두 보관.

## 6. 노션 2회차 — 데일리 브리핑 (한 번에)

notion create-pages, parent: data_source_id = YOUR_NOTION_DATA_SOURCE_ID

페이지:
- 헤드라인: "M/D 반도체 데일리 브리핑" (4단계 날짜)
- date:날짜:start: 4단계 날짜
- date:날짜:is_datetime: 0
- 분야: "[\"반도체\"]"
- 카테고리: "[\"데일리 브리핑\"]"
- 요약: 4단계 작성값

content:
## 오늘의 뉴스
- [선정 뉴스 헤드라인](노션 url) ...

## 본문 추출 실패
- [추출실패 헤드라인](노션 url) ...

## 7. 결과 보고 (간결하게)

3줄만:
1. 처리 N건 → 선정 N건 + 추출실패 N건
2. 카테고리 분포 (선정 기준)
3. 특이사항 (없으면 "없음")
````

---

## 설계 메모

- 2단계의 **영문 쿼터**는 파이썬 쪽 `ENGLISH_QUOTA`와 짝을 이룬다. 파이썬 쿼터는 영문 기사를 `latest.json`까지 살려 보내는 역할만 하고, 실제로 노션 상위 5건에 노출시키는 건 이 프롬프트 규칙이다. 둘 중 하나만 있으면 영문이 안 뜬다.
- 2단계의 **우선 가중**(공정과 양산, 특히 박막공정)은 파이썬의 `BUCKET_WEIGHTS["tech"]=1.3` 및 `TECH_QUOTA=2`와 같은 방향이다. 파이프라인 전 구간이 한 방향을 본다.
- 5단계와 6단계를 나눈 이유는 브리핑 본문에 1회차에서 만들어진 노션 페이지 링크가 들어가야 하기 때문이다. 순서상 합칠 수 없다.
